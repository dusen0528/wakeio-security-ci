# Pinned OSS source benchmark

This benchmark measures Wakeio's built-in source checks against seven independently reviewed source flows in two intentionally vulnerable training repositories. It scans each **entire checkout root** once; the listed vulnerable files are comparison sites, not a reduced scan input. The [locked corpus](../benchmarks/oss-corpus.json) contains full Git commit and tree IDs, SHA-256 hashes of reviewed files, pinned source links, source and sink coordinates, and narrow reviewed negative sites. The independent source review is in [the efficacy evidence note](research/oss-source-efficacy-2026-10-13.md). No upstream source file is checked into this repository.

Run only against existing local checkouts of the pinned commits, after building this trusted package:

```sh
node scripts/benchmark-oss.mjs \
  --checkout juice-shop=/absolute/path/to/juice-shop \
  --checkout nodegoat=/absolute/path/to/NodeGoat \
  --out /absolute/path/to/new-results
```

`--manifest FILE` selects a trusted local corpus. `--profile default|extended` selects the declared AST work budget; `extended` is the default. The source collector is explicitly called with `maxFiles: 10000` and `maxBytes: 134217728`; its per-file limit remains 2 MiB. External tools are explicitly disabled with `tools: []`. These values are within the SDK's public caps. The script does not clone, fetch, install, build, test, start, or make network requests to a target application. It never imports target code. It reads the target files as data in a bounded source snapshot, then calls the trusted local `runSource` build. The output directory must be new and outside both checkouts.

Before and after scanning, the harness verifies each checkout's exact commit/tree and compares every tracked file's raw Git blob hash to disk. It refuses missing tracked files, all extra files (including ignored files), symlinks, submodules, file mode changes, and reviewed-file SHA-256 mismatches. Git commands use fixed arguments and a sanitized environment; hooks and fsmonitor are disabled, and both lazy fetch and Git transports are blocked. Incomplete promisor objects therefore cause a local error rather than a remote fetch. This is a reproducibility and target-code nonexecution boundary, not a general sandbox for malicious operating-system state. The manifest is capped at 1 MiB and 32 repositories; verification caps checkout traversal at 20,000 files, 2 GiB, and depth 64. A checkout that exceeds a cap is refused, never silently sampled.

The run writes `oss-benchmark.json` and `oss-benchmark.md`, plus `report.json`, `report.sarif`, `report.md`, and `agent-report.json` under one directory per repository. The standard reports retain the normal source scan gate; each repository's `scanExitCode` is separate from the OSS benchmark gate. The benchmark JSON binds the corpus and harness SHA-256, aggregate built JavaScript SHA-256, TypeScript parser entry/package and package-lock SHA-256, Node/tool versions, and hashes of all four standard report files. These fingerprints are checked before and after measurement. Reports do not contain copied source files. Keep the whole new output directory together when comparing revisions, and use the identical manifest and profile for both runs.

## Interpretation

The declared positive denominator is **seven source flows**, including two known unsupported NoSQL families. NodeGoat's three `eval` sinks are one flow and require all three correctly traced findings to be `matched`; one or two are `partial_match`. A positive match requires `kind: candidate`, the exact rule/check, pinned sink path/line/column, and an untruncated `staticFlow` with the declared source and sink steps. A same-location candidate without that trace remains unreviewed and is recorded as `trace_mismatch` or, if the check's scope is incomplete, `unevaluable_scope`. A candidate's presence is evidence of a static pattern, not exploit verification.

The outcome fields distinguish `matched`, `partial_match`, `trace_mismatch`, `missed_evaluable`, `missing_known_unsupported`, and `unevaluable_scope`. Matched findings are retained even when the overall scan is partial, with `scopeComplete: false`. An expected source path that was not collected, AST parse/index/work limits, check errors, and declared exploratory model limits prevent a missing supported site from being called an evaluable miss. Known unsupported NoSQL paths remain in the primary declared denominator and have a separate missing category even if the scan is partial; collection gaps are annotated independently. `declaredObservedFraction` is matched flows divided by all seven declared flows. It is an observed fraction, **not** a population recall estimate. `supportedRecall` is `null` whenever a supported site's scope or the whole scan is incomplete.

All unmatched scanner output remains `unreviewedCandidates`, `unreviewedObservations`, or `unreviewedAdvisories`; a reviewed negative-site overlap is counted as `unexpectedAtReviewedSite`, not automatically as a false positive. Juice Shop's `data/static/codefixes` are unmounted source examples, not live safe controls. Its registered address route is a negative control only for SQL string interpolation, not for authorization or whole-route safety. The known unsupported NoSQL negative example is `not_assessed_unsupported` and cannot be counted as a passing scanner control. `precision` and `falsePositives` remain `null` until **every** candidate in a predeclared measurement set has independent adjudication. Nothing in this benchmark establishes full OWASP coverage, runtime exploitability, fixed behavior, or production safety.

Exit code `0` requires a complete scan, every declared positive flow matched, and no candidate at a reviewed negative site. Code `1` means the completed measurement has an unmet declared positive or a reviewed-site overlap. Code `2` means checkout/manifest/integrity failure or incomplete scan coverage; it is never a clean result. The standard `scanExitCode` can differ because it applies the product's usual high-severity gate, while the benchmark gate measures this locked source corpus.
