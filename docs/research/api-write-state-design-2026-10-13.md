# Owned PATCH persisted-state contract (2026-10-13)

Root approved a standalone owned synthetic increment at baseline `54ecc43aeed3e24e040826ad6a64456f8af1e7d2`. Existing API policy v2, GET transport/ledger, read-only state pilot and its delivery contract remain unchanged. No external staging target, handler/observer injection, arbitrary policy, repeat, model or automatic patch operation is accepted. Implementation author does not build/test/scan/Git; root owns independent verification.

## Public contract

CLI: `api-write-state --candidate fixed|ineffective|all-deny|normal-regression|status-only|wrong-object --active-consent --out NEW_DIR [--timeout-ms N]`. Help/banner explicitly identify owned synthetic PATCH resources. SDK: `runOwnedApiWriteStatePilot({candidate,activeConsent:true,timeoutMs?,signal?})` and delivery-only `deliverOwnedApiWriteStatePilot(result,{outDir?,storage?})`. All options are snapshotted before work; unsupported options/accessors and missing consent reject before target setup.

Each fresh baseline/candidate phase has 18 logical requests: two identities before/after (4), then for each of two resources `GET before → owner PATCH → GET normal → peer PATCH → GET peer → anonymous PATCH → GET anonymous` (14). Total planned/max HTTP attempts **36**, maximum PATCH attempts **12**. This replaces provisional 10/32 limits. No write/address/socket/redirect retry exists. Default/max deadline 30s through `createApiRunControl(...,30000)`; request 4KiB, response 64KiB, shared response budget 1MiB, state file 64KiB, cleanup 2s and delivery 5s. `stateObservations` counts the before/after mutation-window snapshots, not every store read. Cancellation stops subsequent HTTP; an already sent mutation cannot be undone or assumed cancelled. Bounded cleanup and any observed effects are retained; no hard preemption/process sandbox guarantee.

Trusted store primitive validates bounded persisted row fields but does **not** enforce actor ownership. Pinned owned handlers make that decision. Observer uses a separately opened `O_RDONLY|O_NOFOLLOW` FD, with file/path inode binding before/after reads; handler writes use `O_RDWR` and fsync. Independent snapshots, actual arrival actor/method/resource/ordinal and trusted write records bind each mutation window. The intended title must equal the private request marker when a mutation occurs; owner/id/canary, contents and the entire other row must remain unchanged. Any unexpected row/field/value change adds `write_mismatch` and stays partial, even if an unauthorized effect was observed. HTTP acknowledgements are not the state oracle.

Variants: `fixed` denies peer/anonymous without changing state and preserves owner writes (0); `ineffective` returns peer 403 after persisting the requested title (1 only with all prerequisites complete); `status-only` returns 200 without peer/anonymous mutation while owner writes work (0 for scoped mutation denial, not HTTP denial); `all-deny` fails owner controls (2); `normal-regression` alters an unintended normal field (2); `wrong-object` alters another row (2). Every unmet identity/normal/state/integrity prerequisite yields partial/2. Concrete effect/regression observations remain findings after later failures. Baseline must demonstrate a matching unauthorized peer mutation and normal owner function before candidate execution. Candidate names never determine verdicts.

## Evidence, delivery and integration

Additive `apiWriteStateEvidence` lives on `CheckResult`/agent check; version 1, scope `owned-synthetic-resource-patch-write`, phase `baseline|candidate|comparison`, execution `completed|partial|error`, effect `observed|not_observed|unknown`, normal `passed|failed|unknown`, verification `not_evaluated|scoped_fix_effect_observed|effect_persists|normal_regression|inconclusive`, cleanup, bounded reasons/counts/lineage, and separate `ApiWriteExecutionLedger`. This ledger contains fixed canonical method-bearing GET/PATCH plan indexes, attempted/outcome/status; it never masquerades as the GET v2 ledger. Completed/evaluated metadata must have consistent status/count/normal/verification semantics. Strict allowlists reject unknown nested keys; malformed or missing required evidence cannot render a completed oracle. Check ID is `api.owned-write-state-oracle`; findings remain observations with existing independent-verification flags unchanged. JSON/agent/Markdown/SARIF preserve the same safe metadata. Changed/lost write evidence makes generic comparison unverified; the independent observer owns the scoped verdict. Current advice projection omits new write fields and grants no execution/replay authority.

Result: `ApiWriteStatePilotResult {version,scope,runId,before,after,verification,verificationGate,execution}`; phase `{report,scanGate,evidence}`. Receipt: `ApiWriteStateDeliveryReceipt {version,runId,deliveryAttemptId,outputRelativePath,status,reason,verificationExitCode,finalExitCode,artifactSha256,reportDigests,apiReexecuted:false}`. Delivery retries reuse immutable redacted bytes and a fresh unique attempt; they do not issue HTTP. Local files stage privately, then the complete directory is renamed to `OUT/<runId>/<attemptId>` containing `{before,after,verification}/{report.json,agent-report.json,report.md,report.sarif}`, `api-write-manifest.json`, and last `api-write-delivery.json` publication-only marker. Missing phases are absent; a complete three-phase bundle has 14 files. Manifest shape is `{version:1,scope,runId,deliveryAttemptId,artifacts:[{path,bytes,sha256}]}`: only generated phase files, ordered before/after/verification then report.json/agent-report.json/report.md/report.sarif, UTF8 byte lengths and hashes. Marker `manifestSha256` binds its exact UTF8 bytes including the final newline. The marker requires caller acknowledgement and does not prove final process exit. Filesystem publication is not a cross-storage transaction; timeout/cohost/late I/O can leave delivery unknown, and cleanup must never remove an unowned preexisting staging or final destination.

Npm includes pinned `workers/api-write-state` assets. Normal SDK lineage hashes the compiled observer module; bundled CLI lineage uses `observerBasis:'bundled-runtime'` and the actual bundle digest. Direct `dist-action` CLI invocation verifies the bundle, not the composite Action. Root assigned `actions/api-write-state` wrapper/workflow/package-source scope to the research agent as a separate explicit owned Action surface.

The increment gives a runnable CI gate/report for false-denial status patches, owner no-ops and wrong-row/field regression. It establishes reusable bounded request/observation/delivery boundaries; it does not yet exercise users' real APIs. Eventual staging integration needs a separately approved observer/state adapter and explicit resource mutation/reset permissions. Fixture success is not production authorization or fix certification.
