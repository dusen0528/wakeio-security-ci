**Receiver and guard controls.** MarsDB's [pinned package manifest](https://github.com/c58/marsdb/blob/33856a1f929d46cbb6b4ea4a463fde3ded0f6278/package.json#L1-L4) declares 0.6.11 and [its `Collection` API](https://github.com/c58/marsdb/blob/33856a1f929d46cbb6b4ea4a463fde3ded0f6278/lib/Collection.js#L136-L230) accepts selectors in `remove`, `update`, `find`, `findOne`, `count`, and `ids`; a same-named method on an unrelated or shadowed object is not this sink. [Juice Shop declares `marsdb: ^0.6.11`](https://github.com/juice-shop/juice-shop/blob/e39a3bdb8c61295c31fa4e0a03485e68a8ca12a4/package.json#L129-L132), but this source review did not resolve or execute a target installation. The unmounted [Juice Shop code-fix example](https://github.com/juice-shop/juice-shop/blob/e39a3bdb8c61295c31fa4e0a03485e68a8ca12a4/data/static/codefixes/noSqlReviewsChallenge_3_correct.ts#L1-L13) checks `typeof req.body.id === 'string'` before the update and omits `multi: true`: it is an **educational guard pattern**, not a scanner negative proof or a live fixed-route result. A repeated `req.body.id` read can invoke a getter and return a different value; the request-shaped root does not prove stable plain data. The bounded scanner exclusion therefore requires a once-read local `const` snapshot, a dominating terminating string guard, and the remaining identity/mutation checks. That exclusion applies only to the fixed-field selector role while the captured value stays a string; parsing it back to an operator object would remove that protection. `req.body.message` in `$set` is a data value, not this selector source.

For NodeGoat, `parseInt(userId)` at DAO line 58 does **not** sanitize `threshold`. The proposed `parseInt(threshold, 10)` plus range check at lines 64–75 is inside a comment and is not executable protection. In a synthetic safe counterpart the parsed numeric value, rather than the original string, must feed the predicate; `typeof threshold === 'string'` or `String(threshold)` is **not** a safety guard for interpolation into JavaScript. A constant `$where`, a tainted template with no database sink, and a spoofed non-Mongo `find` receiver are negative controls. [NodeGoat source](https://github.com/OWASP/NodeGoat/blob/c5cb68a7084e4ae7dcc60e6a98768720a81841e8/app/data/allocations-dao.js#L57-L86).

**Acceptance and benchmark state.** A new rule needs complete source→sink evidence at the exact pinned sites, stable roles/coordinates through the cross-file aliases above, and tests for the positive cases plus the receiver/guard negatives. Missing cross-module evidence stays incomplete; a method name or `$where` token alone is insufficient. The original corpus at Git commit `5148a43` declared both flows `known_unsupported`. The independently reviewed J3-only revision marks Juice Shop as `exploratory` with exact source/sink evidence; NodeGoat remains `known_unsupported` pending independent verification. The historical five-to-six observed-flow comparison re-evaluates stored results under the same revised oracle; it is not a rerun of the old engine or verification of later engine changes. Further support/rule-ID reclassification requires independent review and a fresh whole-checkout measurement with the **same seven expected flows, commits, and file hashes**. Do not turn a partial scan or an unreviewed candidate into a match, clean negative, precision, or production efficacy claim.

**Implemented synthetic boundary.** The bounded legacy MongoDB 2.x source model is implemented and tested on synthetic fixtures: collected package/lock contract evidence, a recognized `MongoClient.connect` callback Db argument, `db.collection`, and selector/data separation. A narrow constructor-owned arrow and immutable-capture path carries source evidence through declared local/relative-module calls. This is not general closure or modern-driver support, installed-package verification, or a database runtime test; unmaterialized contexts and unresolved identity can still make a synthetic positive partial.

The separate whole-checkout measurement `nosql-root-final-corpus` retains six of the same seven flows with unchanged budgets and benchmark exit `2`. NodeGoat N2 remains `known_unsupported`: propagation first stops at `server.js:132`, `routes(app, db)`, where noncanonical/dynamic global `require` references prevent the CommonJS identity proof. Synthetic support does not satisfy this pinned flow oracle. This later measurement is separate from the historical five-to-six retrospective comparison and does not revise the corpus.
