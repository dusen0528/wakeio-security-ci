# Source expansion implementation notes

This change adds an optional Bandit adapter and bounded local framework candidates to the source scan. The Bandit adapter is opt-in (`bandit` is not part of the three-tool default), uses an externally prepared executable, and never installs Python packages or runs target Python. It stages only collected `.py` files, invokes Bandit with explicit file paths, `-f json`, and `--ignore-nosec`, and runs through the existing argv-only bounded process runner with a private home and stripped environment.

Bandit's documented JSON formatter provides `errors`, `metrics`, and `results`. The parser requires the envelope, generated timestamp, `_totals`, and per-file `loc` metrics for every selected Python file. It maps only staged paths, rejects malformed required fields and unsupported severity/confidence/rule identifiers, treats scanner errors or missing per-file metrics as incomplete, and omits `code`, `issue_text`, filenames outside the snapshot, and arbitrary metadata from findings. Common rule IDs receive fixed guidance and links to the official Bandit documentation.

The framework check is local and candidate-oriented. It inspects only `supabase/migrations/**/*.sql` for uncommented explicit RLS disables and public policies with `USING (true)` or `WITH CHECK (true)`. Policies are medium review candidates, restrictive policies are excluded, and a disable followed by an enable for the same table in the same migration is not reported as the final state. It also inspects recognized JavaScript/TypeScript client or React files for shaped `sb_secret_` literals or JWT payloads whose `role` is `service_role`, plus low-confidence name candidates for `NEXT_PUBLIC` variables associated with server secrets. Supabase publishable/anon key shapes and backend-only role labels remain outside the high-confidence rule.

For the v0.3 preview, these rules do not execute application code, import target configuration, inspect deployed bundles, resolve complete Next/React build boundaries, or query live Supabase grants/RLS state. SQL migration history is evidence for review, not proof of the effective database state.

References: [Bandit command-line options](https://bandit.readthedocs.io/en/latest/man/bandit.html), [Bandit JSON formatter](https://bandit.readthedocs.io/en/latest/formatters/json.html), [Bandit configuration behavior](https://bandit.readthedocs.io/en/latest/config.html).
